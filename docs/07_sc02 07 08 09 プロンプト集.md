# Claude Code プロンプト集（SC02 / SC07 / SC08 / SC09 実装用）

## 使い方

1. `docs/06_画面補足仕様書.md` をリポジトリの `docs/` に追加済みであること
2. 各プロンプトは「バックエンド → フロントエンド」の2分割。1つ完了→動作確認→ `/clear` →次へ進む
3. 共通部品（YearSelector等）はフェーズAで先に作り、以降で再利用させる（重複実装＝トークン浪費を防止）

### トークン削減のポイント
- 読ませるファイルは `06_画面補足仕様書.md` の該当セクションのみ（03の全文は読ませない）
- バックエンド/フロントを分割し、各セッションのコンテキストを半分以下に抑える
- 共通コンポーネントを先に1回だけ作らせ、以降は「既存の○○を使え」で済ませる
- レスポンス形式を06に明記済みなので、APIの型定義で迷わせない

## フェーズD：SC08 収支可視化画面

### D-1. バックエンド（収支可視化API）
```
docs/06_画面補足仕様書.md の「SC08 収支可視化画面」の「APIレスポンス形式」のみ読んで。

GET /api/v1/summary/visualization?year= を実装して。

計算方針:
- monthlyAverage: incomes, pre_savings, transactionsの月平均（データのある月数で割る）
- annual: 年間合計（臨時収入・賞与含む全データ）
- expenseRatio / savingRatio: 分母0ガードあり(0を返す)
- monthlyRatios: 月ごとの支出率・貯蓄率（グラフ用、12要素の配列）

既存の按分・比率計算ロジックを再利用すること。
単体テスト: 収入0の月のゼロ除算ガード、データなし年。
まず実装計画を箇条書きで出して。
```

## フェーズE：SC09 資産管理画面

### E-1. バックエンド（資産API）
```
docs/06_画面補足仕様書.md の「SC09 資産管理画面」の「使用API」のみ読んで。
テーブル定義が必要なら docs/03_詳細設計書.md の 1.8 assets と 1.9 asset_balances のみ読んで。

以下のAPIを実装して:
- GET /api/v1/assets?assetGroup=
- POST /api/v1/assets
- PUT /api/v1/assets/:id
- GET /api/v1/asset-balances?year=
  レスポンスに人別小計・合計を含めて返すこと
- PUT /api/v1/asset-balances/bulk
  [{assetId, year, month, balance}, ...] を受け取りupsert

Prismaスキーマに assets, asset_balances が未定義ならマイグレーション追加も行って。
まず実装計画を箇条書きで出して。
```
