# 起動手順書

開発環境でアプリを起動するための手順。

## 前提
- Docker（Docker Compose）
- Node.js
- `backend/.env` に `DATABASE_URL`・`JWT_SECRET` が設定済みであること

## 1. MySQLコンテナ起動

```
docker-compose up -d
```

`docker-compose.yml` により、`kakeibo`データベース・`kakeibo_user`ユーザーでMySQL 8.0コンテナが起動する（ポート3306）。

## 2. バックエンド起動

```
cd backend
npm install          # 初回のみ
npm run prisma:generate   # Prismaスキーマ変更後は必要
npm run dev
```

- ポート3001で起動（`ts-node-dev`によるホットリロード対応）
- DBスキーマ未適用の場合は事前にマイグレーション適用が必要（下記「補足」参照）

## 3. フロントエンド起動

```
cd frontend
npm install          # 初回のみ
npm run dev
```

- ポート5173で起動（Vite）。使用中の場合は5174等へ自動でずれる

## 4. ブラウザでアクセス

`http://localhost:5173` を開き、開発用アカウントでログインする。

| メールアドレス | パスワード |
|---|---|
| taiyo@example.com | kakeibo1234 |
| mirano@example.com | kakeibo1234 |

household_id=1（ユーザー「たいよう」「みらの」）に紐づく開発用アカウント。

## 補足：マイグレーション適用について

`kakeibo_user`にはシャドウDB作成に必要な権限（`CREATE, DROP, ALTER, REFERENCES, INDEX`）は付与済みだが、シャドウDB上でのDML（`UPDATE`等）実行権限は付与されていないため、`npm run prisma:migrate`（`prisma migrate dev`）はデータ移行を伴うマイグレーションで失敗する場合がある。

新規マイグレーションが必要な場合は、`prisma migrate dev`ではなく以下の手順で行うこと。

```
cd backend
npx prisma migrate deploy   # シャドウDBを使わず直接DBに適用
npx prisma generate
```

## テスト実行

```
cd backend && npm test
cd frontend && npm test
```

## Excelデータ移行（初期データ投入時）

```
cd backend
npm run migrate:excel -- <xlsmパス> <household_id>
```
