# 割り勘計算機能 仕様書（F16）

現行Excel「27年1月」シートのM51:P53（割り勘計算）およびB84:E87（計算領域）の解析結果に基づく仕様。
Claude Codeは本ファイルの該当セクションのみ読むこと。

---

## 1. 現行Excelロジックの解析結果

### 1.1 該当セル

| セル | 内容 |
|---|---|
| Z列（6〜159行） | 割り勘マーカー（☀ / ☆ / ♠ / ♡）※支出明細テーブルの拡張列。空欄＝精算対象外 |
| AA列（6〜159行） | 半端額（第1.2版で追加。後述） |
| B84:E84 | マーカー別のAA列合計 `SUMIF(Z:Z,"マーカー",AA:AA)` |
| B85:E85 | マーカー別のX列(金額)合計 `SUMIF(Z:Z,"マーカー",X:X)` |
| B86 | `=(B85+C85)/2` 折半対象総額の半分＝1人あたり公平負担額 |
| C86 | `=B86-B85` |
| D86 | `=D85-E85` |
| B87 | `=C86+D86+B84+E84-C84-D84` 最終精算額 |
| M52 | `=IF(B87>0,"たいよう→みらの",IF(B87<0,"みらの→たいよう",""))` 精算方向 |
| O52 | `=B87` 精算金額 |

### 1.2 マーカーの意味（数式から逆算・検証済み）

各マーカーは「**誰が立て替えて払ったか**」×「**誰が負担すべきか**」の組み合わせを表す。

| マーカー | 立替払いした人（payer） | 費用負担 | 意味 |
|---|---|---|---|
| ☀ | たいよう | 折半（50:50） | たいようが払った共同支出 |
| ☆ | みらの | 折半（50:50） | みらのが払った共同支出 |
| ♠ | みらの | 全額たいよう負担 | みらのがたいようの分を立て替え |
| ♡ | たいよう | 全額みらの負担 | たいようがみらのの分を立て替え |

### 1.3 AA列（半端額）の意味

第1.2版「割り勘の会計にて、半端の額づつ支払った際の対応」で追加された列。

**定義：その取引において「立替払いした人ではない方」が、その場で現金等で直接負担した額。**

例）5,000円の食事をたいようがカードで払い、みらのがその場で現金2,000円を渡した場合
→ Z列=☀、X列(金額)=5,000、AA列(半端額)=2,000

AA列は常に「立替者の債権を減らす」方向に作用する（4マーカーすべてで統一）。

### 1.4 計算式の展開と意味

```
B87 = (C85 - B85)/2 + (D85 - E85) + B84 + E84 - C84 - D84
```

これは以下と数学的に完全一致することを検証済み：

```
公平負担額(fair)     = (☀のX合計 + ☆のX合計) / 2
たいようの実質拠出   = (☀のX合計 - ☀のAA合計) + ☆のAA合計
折半分の債務(owe_half) = fair - たいようの実質拠出
全額負担分(owe_full) = (♠のX合計 - ♠のAA合計) - (♡のX合計 - ♡のAA合計)

B87 = owe_half + owe_full
```

### 1.5 符号ルール

| B87 | 表示 | 意味 |
|---|---|---|
| > 0 | 「たいよう→みらの」 | たいようがみらのに支払う |
| < 0 | 「みらの→たいよう」 | みらのがたいように支払う |
| = 0 | 空欄 | 精算不要 |

金額表示は絶対値を用いること（Excelは負値のまま表示しているが、UI上は方向ラベル＋絶対値が適切）。

### 1.6 既存「人(V列)」との関係

V列（たいよう/みらの/両方）は**費目集計上、誰の支出として計上するか**を決める軸。
Z列は**誰が立て替えたかの精算軸**であり、両者は独立している（Excelでも別列）。
DB設計でも別カラムとして保持し、混同しないこと。

## 2. DB設計変更

`transactions` テーブルに以下3カラムを追加する（すべてNULL許容＝精算対象外の取引はNULL）。

| カラム名 | 型 | NULL | 説明 |
|---|---|---|---|
| settlement_payer_user_id | BIGINT UNSIGNED FK→users.id | NULL | 立替払いした人。NULL＝精算対象外 |
| settlement_burden | ENUM('half','other_full') | NULL | 'half'＝折半、'other_full'＝全額相手負担 |
| settlement_partial_amount | DECIMAL(10,0) | NULL | 半端額（相手がその場で現金負担した額）。デフォルト0 |

### マーカー ⇄ カラムのマッピング

| Excelマーカー | settlement_payer_user_id | settlement_burden |
|---|---|---|
| ☀ | たいようのuser_id | 'half' |
| ☆ | みらののuser_id | 'half' |
| ♠ | みらののuser_id | 'other_full' |
| ♡ | たいようのuser_id | 'other_full' |
| （空欄） | NULL | NULL |

> 4マーカーを2カラムに正規化することで、世帯人数が増えても破綻しない構造とする。

- INDEX: `(household_id, settlement_payer_user_id)`
- CHECK相当のバリデーション（アプリ層）: `settlement_payer_user_id` がNULLでないなら `settlement_burden` も必須。

## 3. 精算ロジック（実装仕様）

### 3.1 汎用アルゴリズム（2人世帯前提）

対象：指定年月の `transactions` のうち `settlement_payer_user_id IS NOT NULL` の行。
メンバーAを基準（user_id昇順の先頭）、メンバーBを相手とする。

```
netA = 0  // 正ならA→Bへ支払う

各取引 t について:
  amount  = t.amount
  partial = t.settlement_partial_amount ?? 0
  fronted = amount - partial     // 立替者が実質立て替えた額

  if t.settlement_burden == 'half':
      share = amount / 2         // 各自の公平負担額
      if payer == A:
          netA += share - fronted        // Aが払った分
      else:
          netA += share - partial        // Bが払った分、AはpartialだけAが現金拠出済み
  else: // 'other_full' 全額相手負担
      if payer == A:
          netA -= fronted        // AがBの分を立て替えた → Bが債務者
      else:
          netA += fronted        // BがAの分を立て替えた → Aが債務者
```

`netA > 0` → 「A→B」、`netA < 0` → 「B→A」、`0` → 精算不要。表示金額は `abs(netA)`。

### 3.2 端数処理

`amount` が奇数円で `burden='half'` の場合、`share = amount / 2` は0.5円が発生する。
**Excelは丸めずに小数のまま合算し、最終結果のみが表示される**ため、同一挙動とするには
「各取引では丸めず、最終合計 `netA` に対してのみ `Math.round()` を適用」すること。
取引ごとに丸めると現行Excelと結果が乖離するので注意。

### 3.3 既存の費目按分ロジックとの関係

`docs/03_詳細設計書.md` 5.1の按分ロジック（split_type='shared'を÷2する処理）とは**別物**。
精算計算は費目集計に一切影響を与えないこと（読み取り専用の集計として実装する）。

## 4. API仕様

| メソッド | パス | 概要 |
|---|---|---|
| GET | /api/v1/settlements?year=&month= | 指定月の精算結果を取得 |

### レスポンス形式

```json
{
  "year": 2027,
  "month": 1,
  "direction": "A_TO_B",
  "fromUser": {"userId": 1, "displayName": "たいよう"},
  "toUser": {"userId": 2, "displayName": "みらの"},
  "amount": 12500,
  "breakdown": {
    "halfSplit": {
      "totalAmount": 80000,
      "fairShare": 40000,
      "contributedByFrom": 27500,
      "subtotal": 12500
    },
    "otherFull": {
      "subtotal": 0
    }
  },
  "transactionCount": 14
}
```

- `direction`: `"A_TO_B"` / `"B_TO_A"` / `"NONE"`（精算不要）
- `amount`: 常に正の整数（絶対値）
- `direction="NONE"` の場合 `fromUser`/`toUser` は null
